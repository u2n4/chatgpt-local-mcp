# Edge Project Bridge V0.5.0 canary architecture

The Rust broker owns authentication, request admission, project authorization and durable queue records. BridgePulse uses the loopback owner endpoint. The legacy stdio MCP adapter preserves the production read path. The binary retains the V0.4.0 compatibility identifier for this source prerelease.

| Boundary | Behavior | Verification |
| --- | --- | --- |
| HTTP transport | Loopback listener, host check, independent owner/edge/executor credentials, HMAC replay windows per authenticated principal | Legacy and modern loopback MCP test clients |
| Control requests | Up to 4 active and 24 total, with up to 3 active and 16 total per credential | Separate request admission and timing header |
| Common requests | Up to 8 active and 32 total, with up to 6 active and 24 total per credential | Independent work on bounded blocking workers |
| Heavy requests | Up to 4 active and 16 total, with up to 3 active and 8 total per credential | Bursty requests receive structured retryable `RESOURCE_BUSY` |
| Durable admission | SQLite WAL with FULL synchronization, scoped operation id, payload and grant checks | Disconnect, replay, mismatch and broker restart using fixtures |
| Files | File handles, expected preimages and journaled backups. Bridge patch writers and rollback use an OS lock per root within one state directory | Same-preimage checked writes and rollback tests |
| Cancellation | Unstarted requests transition to `cancelled`; running ones transition to `cancelling` until a supervisor finishes cleanup | Compare-and-swap job state, isolated owner MXC path |
| Execution | Queue acceptance and process supervision are distinct. The owner's MXC runtime accepts a scoped local Python test recipe | Explicitly approved fixture files and signed evidence |
| Remote coding | Activation requires an independently verified fully confined provider and a verified included-only route for that provider | See the executor guide |

HTTP queue deadlines are 120 ms for control and 300 ms for other workers. A started request retains its worker permits until it returns even if its HTTP client disconnects. The scheduler bounds request work. The socket lifecycle and buffered transport responses have separate limits. Existing HTTP authentication maps all executor tokens for this surface to one configured executor identity, `executor:default`. Clients sharing one credential share its capacity and ownership.

The DB write busy timeout is 75 ms. A conflicting write reports a retryable busy reason. The DB commit precedes queue acknowledgement. Safe queued rows remain queued across restart. Potentially started rows become `unknown` and require reconciliation. Operation-id deduplication continues to prevent duplicate acceptance.

Three schema families are tracked separately: MCP wire revisions, bridge contracts, and the SQLite schema number. The prerelease adds information to the source contracts while retaining the installed runtime's compatibility version.
