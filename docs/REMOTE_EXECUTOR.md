# Delegated executor

| Identity | Entry point | Scope |
| --- | --- | --- |
| edge | Existing read connector or dedicated edge bearer on loopback | Reads on projects granted to edge |
| executor:default | Loopback MCP with the distinct executor bearer | Project and recipe from an active owner-issued task grant |
| local | Local CLI and owner bearer | Owner administration and approval |

Prepare the isolated service with the `canary` or `synthetic` environment flag. Register one approved fixture root and create a short-lived grant for `executor:default`. Without `--profile` or `--writable-path`, `edge-bridge grant-create` gives `read`, `git_read` and `execute_recipe` for the requested `--recipe` values (default `python_tests`) and no writable path (`writable_paths: []`); pass `--profile pro-review` for create-only writes under `_pro/**` with `python_tests` and `powershell_script`, or pass explicit `--writable-path` allow patterns (which also adds `write`, `patch` and `checkpoint`). A delegated principal can never create or patch files under `_pro/inbox/` under any grant, old or new. Keep the credential files in the broker state directory. Load the executor bearer into the client in memory through the client’s secret mechanism. Its grant specifies the project, operations and recipes. Keep the owner credential with the controller.

The approved client can call `policy_view` with `project_id` and optional `grant_id` to inspect the active grant's limits under `grant` (`grant_id`, `permitted_categories`, `writable_paths`, `denied_paths`, `allowed_recipes`, `export_scope`, `limits`, `expires_at`). When a delegated call omits `grant_id`, the bridge selects the newest grant valid for that principal, project, host and current policy revision (not revoked and not expired); with an explicit `grant_id`, that specific grant is checked or refused. `limits` holds the values stored in the grant; for enforced limits the queue worker applies the lower of the fixed recipe cap and the grant's stored value (see the table below), while a value above the fixed cap changes nothing and a value of `0` (or one that cannot be applied) refuses the run with `INVALID_GRANT_LIMITS`. It can call `task_submit` with `project_id`, `task_id`, `operation_id`, `grant_id`, `recipe`, and `args`. Use the same operation id for an identical retry. Keep the returned `run_id` and pass it as `job_id` to `job_get` and `job_output` with the same grant. A delegated `job_cancel` call uses the same grant. The broker authorizes cancellation against the recipe stored with the run. `artifact_list` lists sealed manifests for the caller and grant, including `execution_outcome`, `agent_outcome`, and `verification_outcome` next to `verdict`; pass a listed `manifest_id` to `artifact_read` as `artifact_id`.

## Owner queue worker

`execution_mode: queue_only` confirms durable admission. The local owner starts `edge-bridge --state-dir <state> worker --runtime-root <trusted-checkout>` from the interactive Windows desktop. The runtime checkout needs the Bridge Python package and its existing `.venv`. The runtime and state directories must be outside the project. Add `--once` to drain the queue and exit when it is empty. The worker fails a delegated run with `PERSISTENT_ENVIRONMENT_HOLDS_CREDENTIALS` while the persistent user or machine environment holds an entry that looks like a credential, because a run can read it; `edge-bridge environment-check` lists the names, and `--allow-environment-credentials` runs anyway. One worker per state directory claims delegated submissions for the local host. The owner can still approve a local-only Python submission with `run-queued-python-tests`.

| Recipe | Request | Snapshot scope |
| --- | --- | --- |
| `python_tests` | Empty `args` | Discovers eligible `.py` and `.json` files up to six levels down in 200 visible entries. Credential-style files and folders hidden from remote principals (such as `auth.json`, `.env`, `credentials.*`, and the other paths matched by `is_hidden_from_remote`) are skipped during discovery: the bridge does not copy, count, hash or name them, and a test that needs one fails inside the run because the file is absent. The suite needs `tests/__init__.py` and at least one top-level `tests/test_*.py`. The worker rejects more than 32 snapshot files or a request line over 64 KiB before spawning the supervisor. The supervisor requires canonical names and enforces 64 KiB per file and 512 KiB total. |
| `powershell_script` | `args` contains one canonical project-relative `.ps1` path | The recipe grant authorizes any eligible script at that path. The worker snapshots the one script and invokes it with pinned PowerShell 7 using `-NoProfile -NonInteractive -File`. The MXC profile is the execution boundary. Extra script arguments are refused because the pinned supervisor does not yet bind them into its verified command. |

The durable run stays `admitted` while the supervisor stages the snapshot and runs its containment preflight. Rust uses the broker's protected filename policy in `crates/bridge-core/src/files.rs` to select the permitted source paths. The Python supervisor checks the exact allowlist before reading any staged source. Immediately before creating the workload process, the supervisor waits for a one-use launch reply. The transaction that authorizes launch and marks the run `running` checks the original grant, its expiry, project revision and cancellation together. Every retry repeats that check against the current state. A denied launch or failed containment canary ends preparation without creating the workload process. A cancellation committed after that transaction follows the running cancellation path. The supervisor locks and hashes the pinned Codex image for each preflight and workload launch. It keeps the image and its resolved directory path locked through process creation. For PowerShell it holds the same locks until the job tree exits because Codex starts that child asynchronously.

`job_output` pages the bounded, redacted capture by `next_seq`. The Python runner captures stdout and stderr in one stream of at most 256 KiB, or less when the grant sets a lower `max_output_bytes`, exposed as `combined` in chunks of at most 4 KiB. Request denial and supervisor failure codes use `stderr`. The worker stores the run output chunks in one transaction. The owner can inspect a signed manifest for captured output and containment provenance after the supervisor confirms workload startup and the process tree exits. The manifest and `job_get.workload_report` label the exit code and parsed counts as reported by the workload. The workload controls its output. The independent verification field reads `NOT_TESTED` for workload-reported results, including previously stored delegated runs with sealed capture. PowerShell has no test-count parser. The worker rejects non-exportable request metadata before starting the supervisor. An evidence rejection or early supervisor exit with confirmed process-tree cleanup fails the affected run and the worker continues draining the queue. Worker store operations retry temporary SQLite contention with a finite budget. If evidence finalization fails in the store, the worker stops and the run becomes `unknown` immediately or at the next startup if the store is still unavailable. The worker resolves completion and cancellation in one transaction that commits the terminal state and its matching signed manifest together, then publishes any local evidence files. Cancellation committed before that decision wins, and cancellation requests after commit return the recorded state.

A queued cancellation prevents admission. A running cancellation asks the supervisor to terminate its Job Object. The worker confirms the outer process tree has exited before recording `cancelled`. If the supervisor hangs, the worker terminates the outer Job Object and confirms its exit. Cancellation before launch and forced cleanup without a receipt produce no workload manifest. The worker removes the workspace and raw supervisor state after confirmed exit. On restart, the worker holds the exclusive lease while sweeping leftovers from dead workers. Windows terminates their process trees when their Job Object handles close. A cleanup failure is reported in the signed manifest and the affected file is left for the next sweep. An unfinished delegated run becomes `unknown` and is never replayed automatically.

| Resource | Current behavior |
| --- | --- |
| Concurrency and wall time | One delegated workload per worker, a supervisor deadline of `min(60 s, grant.limits.max_duration_seconds)`, and an outer deadline (`+15 s`) for a stalled supervisor. A grant value of `0` is refused with `INVALID_GRANT_LIMITS`. |
| Containment | Per-job MXC preflight, no network, `min(8, grant.limits.max_processes)` processes, and `min(768 MiB, grant.limits.max_memory_mb)` of memory in the recipe job. A grant value of `0` (or one Windows rejects) is refused with `INVALID_GRANT_LIMITS`. |
| Snapshot and workspace | The snapshot input limits above apply. The supervisor polls logical workspace file sizes and fails the run at more than `min(256 MiB, grant.limits.max_storage_bytes)` (32 MiB under the default grant limits), more than 16,384 entries, or an observed reparse point. The scanner samples logical file sizes. There is no enforced byte bound on overshoot. A single large write can exceed the cap before the next observation, many small files can delay a scan, and alternate data streams are uncounted. Filesystem allocation and metadata also fall outside the sample. |
| Output | Capture is limited to `min(256 KiB, grant.limits.max_output_bytes)` per run and chunked as described above. Retention and total stored output rows across runs are open. |
| Queue and CPU | The number of queued runs per grant and a CPU share limit are open. `grant.limits.max_cpu_percent` is stored on the grant but not applied by the worker (except that `0` is refused with `INVALID_GRANT_LIMITS`). |

A full state volume stops the worker when it cannot write controller state or finalize a run. Put the state directory on a volume with a quota that leaves room for controller writes, or reserve enough free-space margin for the workload and its controller records.

For the current stdio read connector, leave its server-side identity set to `edge`. HTTP activation needs a separate private connector configuration to the loopback MCP URL. The tunnel client's extra-header setting can read the executor secret from an external file reference. Verify the exact connector profile, destination and allowed client identity at setup. Keep raw profiles and credential references entirely within the runtime.
