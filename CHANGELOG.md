# Changelog

## Unreleased

- Test runs on real projects: `python_tests` now has the same snapshot limits as `python_tests_work` (128 files, 256 KiB per file, 4 MiB in total, 1,000 entries; before: 32 files, 64 KiB, 512 KiB, 200). Both recipes discover tests when `tests/__init__.py` is absent, without creating a file, and the single-test selector works in both layouts. A refusal for a snapshot limit names the limit and the measured value. `powershell_script` keeps its limits (32 files, 64 KiB per file, 512 KiB).
- Easier Windows setup and daily helpers generated by `scripts/install.ps1`: added `start.ps1` (runs `environment-check`, creates a 240-minute `pro-agent` grant by default with `-Profile`/`-GrantProfile` and `-Minutes` 1..1440, prints a one-line access summary, starts the worker or tells you to run `setup-worker.ps1` while keeping the grant, and gates `--allow-work-exec` behind `-AllowWorkExec` with a 3-line warning and `y/N` prompt), `status.ps1` (binary version, project path/id, worker runtime status, missing test-run prerequisites, `_pro\work\` workspace file counts, and `_pro\outbox\`/`_pro\reports\` listings), `apply.ps1 <workspace>` (validates workspace name, shows dry-run diff, asks `y/N`, applies with `--confirm`, prints `journal_id` and exact `rollback.ps1` command), `rollback.ps1 <journal_id>` (validates `pjr_` journal id and runs `rollback-patch`), `setup-tunnel.ps1` and `start-tunnel.ps1` (configures `tunnel-client` 0.0.21 with `Read-Host -AsSecureString` stored in `<state_dir>\tunnel-runtime.key` via `file:` reference, validates with `tunnel-client doctor`, and starts with `tunnel-client run --profile`); added `-Minutes` (1..1440) and renamed `$Profile` to `$GrantProfile` with `-Profile` alias in `new-grant.ps1`; updated `install.ps1` closing output, `README.md` (English and Arabic), and `docs/INSTALL.md` with a single hash-verified PowerShell bootstrap block and full helper documentation.

- Remote coding-agent workflow (46 MCP tools; `edge` gains nothing):
  - Read ergonomics (non-`edge` only): `file_read`, `file_view`, and `file_read_batch` accept 1-based `start_line`/`end_line` (up to 2,000 lines, mutually exclusive with `offset > 0`); `file_search` accepts `context_lines` (`0..=5`), `file_glob` (up to 64 ASCII chars), and bounded linear-time `regex` (256 KiB compile/DFA limit); `file_list` raises max `limit` from 100 to 500 for non-`edge` (keeping 100 on `edge`). `file_patch` now validates `1..=64` edits before authorization.
  - `pro-agent` grant profile and `work_area` category: `edge-bridge grant-create <project_id> --profile pro-agent` adds `patch`, `work_area`, and `python_tests_work` alongside `_pro/**` (`pro-review` is unchanged). `policy_view` also lists existing workspaces under `work_area`. `new-grant.ps1` in `scripts/install.ps1` accepts optional `-Profile pro-review|pro-agent` (default `pro-review`).
  - Workspace tools (`work_area` grants only, strictly inside exact-case `_pro/work/<workspace>/`, max 16 workspaces, bridge-side baseline manifest in `<state>/work-manifests/`): `work_copy` (1–64 paths, up to 500 files, 4 MiB/file, 32 MiB/call, or intra-workspace single-file copy), `work_edit` (atomic multi-file search-and-replace, 1–32 files, 1–64 hunks, 1 MiB/file, 4 MiB/call), `work_move`, `work_delete` (1–64 files or whole-workspace cleanup with `delete_workspace: true`), `work_diff` (read-only paginated unified diff up to 4 MiB with drift detection), and `work_export_diff` (create-only `git apply`-compatible `.diff` up to 1 MiB under `_pro/outbox/`). `file_write` and `file_patch` also allow hash-checked overwrites strictly inside `_pro/work/<workspace>/**` under `work_area`.
  - Local owner apply CLI: `edge-bridge --state-dir <state> work-apply <project_id> <workspace>` (dry run by default; `--confirm` applies atomically with baseline-drift checks and writes a patch journal reversible with `edge-bridge rollback-patch`). Never exposed as an MCP tool.
  - Async job ergonomics and queue/output bounds: `job_wait` waits 0–20 s for 1–16 runs (`any`/`all`, optional bounded output up to 32 KiB, max 2 concurrent waits per caller); `task_get` includes `workload_report` on delegated runs; `task_submit` caps active/queued runs at 8 per grant (preserving idempotent replay); stored `run_output_chunks` are pruned to the most recent 200 terminal runs.
  - Opt-in `python_tests_work` recipe (off by default): runs standard-library `unittest` (`-I -S -B`, optional single-test selector, max 60 s, work snapshot up to 128 files / 256 KiB per file / 4 MiB total, Win32 Job Object CPU hard cap `min(50%, grant.limits.max_cpu_percent)`, mandatory persistent-environment check unaffected by `--allow-environment-credentials`, `verification_outcome: NOT_TESTED`) only when the worker is started with `--allow-work-exec`; otherwise refused immediately with `WORK_EXEC_NOT_ENABLED`. `powershell_script_work` is refused everywhere with `POWERSHELL_SCRIPT_WORK_UNSUPPORTED`. `scripts/probe_work_sandbox.ps1` measured on one PC that while network and outside folders are blocked, Windows user name/profile paths and `HKCU\Software`, `HKLM\Software`, and `HKCU\Environment` are reachable; docs recommend leaving `--allow-work-exec` off unless that risk is accepted.
  - Updated `initialize` `server_instructions` for delegated principals, tool descriptions across the 46-tool catalog, and documentation (`docs/REMOTE_EXECUTOR.md`, `docs/TOOL_CAPABILITIES.md`, `docs/KNOWN_LIMITATIONS.md`, `docs/PRO_AGENT_MAILBOX.md`, `docs/INSTALL.md`, `README.md`).

- Windows installer: `scripts/package_release.ps1` builds a release zip (the binary, the Python runtime sources, `install.ps1`, the user docs) with `SHA256SUMS.txt`, and `scripts/install.ps1` installs it with PowerShell 7. The installer asks for an install folder and a project folder, verifies the SHA-256 of the zip before it extracts it, checks the prerequisites, builds the Python environment with `uv sync --locked`, registers the project, creates `_pro\inbox`, `_pro\outbox` and `_pro\reports`, and writes four helper scripts. A missing prerequisite of test runs does not stop the install: the core (read, and create under `_pro\`) is installed, the missing items are listed, and `setup-worker.ps1` builds the worker runtime later. It installs only into a new or empty folder and never replaces an existing installation. See `docs/INSTALL.md`.

- Delegated grant resolution and queue-worker limit fixes: when a delegated call omits `grant_id`, authorization now chooses the newest grant valid for that principal, project, host and current policy revision (not revoked and not expired) so a newer expired, revoked, wrong-host or stale-revision grant no longer hides an older valid grant; explicit `grant_id` checks are unchanged. A stored grant whose limits cannot be read gets zero limits, so the worker refuses its runs. The queue worker now applies the lower of the fixed recipe cap and the authorized grant's stored limit for `max_duration_seconds` (capped at 60 s), `max_memory_mb` (capped at 768 MiB), `max_processes` (capped at 8), `max_output_bytes` (capped at 256 KiB) and `max_storage_bytes` (capped at 256 MiB; default grant stores 32 MiB), never loosening a recipe cap, and refuses runs with `INVALID_GRANT_LIMITS` when any grant limit is `0` or cannot be applied; `max_cpu_percent` remains stored only and is not applied.
- Review-grant and discovery security fixes: a delegated principal can never create or patch `_pro/inbox` or any path under `_pro/inbox/` under any grant, old or new (enforced as a fixed policy rule on every delegated grant rather than grant data); the refusal says to write under a path the grant allows and names `_pro/outbox/` and `_pro/reports/` as the ones a `pro-review` grant allows, while reading `_pro/inbox/` still works. The `pro-review` profile grants create-only writes under `_pro/**`, and a grant with the `write` or `patch` category can queue a run only when `_pro/**` is its one writable path. Bare `edge-bridge grant-create` (without `--profile` or `--writable-path`) gives `read`, `git_read` and `execute_recipe` for the requested `--recipe` values (default `python_tests`) and no writable path; an explicit `--writable-path` also adds `write`, `patch` and `checkpoint`. `grant-create` rejects a `--writable-path` that is empty, starts with `!` or `/`, or contains `:`, a backslash or a `..` part, and a `--recipe` that is not a name made of lowercase letters, digits and `_`. Delegated `python_tests` discovery skips credential-style files and folders (the ones hidden from remote principals): the bridge does not copy, count, hash or name them, and a test that needs one fails inside the run because the file is absent.
- Remote MCP usability fixes: `policy_view` takes `project_id` and optional `grant_id` and returns the caller's validated grant limits under `grant` (`grant_id`, `permitted_categories`, `writable_paths`, `denied_paths`, `allowed_recipes`, `export_scope`, `limits`, `expires_at`) for delegated connections without exposing owner names or other grants; `limits` holds the values stored in the grant, and a recipe can apply stricter ones; a stored writable path or recipe that starts with `/` or contains `:` or a backslash is left out; `artifact_read` documents that `artifact_id` takes the `manifest_id` returned by `artifact_list`; `artifact_list` includes `execution_outcome`, `agent_outcome` and `verification_outcome` from the stored manifest alongside `verdict` (without changing verdict computation or signing); and `file_read`/`file_view` descriptions and schemas state that `offset` and `limit` are measured in characters, not lines or bytes.
- Refusal `next_action` hints now match what a remote caller can actually do: the delegated create-only `VERSION_CONFLICT` hint says to choose a new file name, and the delegated overwrite refusal (`expected_hash` supplied) advises omitting `expected_hash` (or setting it to null) and choosing a new file name; for a delegated connection, owner-only tools (`file_move`, `file_delete`, `process_start`, `process_input`, `job_changes`, `task_checkpoint`, `git_checkpoint`, `git_integrate`, `worker_start`, `worker_steer`, `worker_cancel`) state that the tool is owner-only and run locally by the owner; stale grant `policy_revision` advises requesting a new owner grant; and the protected-path, staging-path, short-name and opened-name hints apply to every remote principal, including `edge`, without advising a grant request. Hints for the local owner principal are unchanged.
- Queue worker runs grant-bound Python unittest discovery and single-script PowerShell requests in filtered MXC snapshots, with a launch-time grant and cancellation check, bounded supervisor requests and SQLite retries, sampled workspace limits, and signed reports for started workloads that record raw cleanup results. The terminal state and signed manifest commit together, and inconsistent unittest summaries yield no parsed counts.
- Remote principals (`edge`, executors and paired hosts) can no longer see or write a set of credential folders and files that the Rust file tools used to serve: the Git folder itself (`.git`, whose `config` can hold a token in a remote URL), `.hg`, `.svn`, `.ssh`, `.aws`, `.azure`, `.gnupg`, `.kube`, `.terraform`, the tool folders `.codex`, `.claude` and `.agents`, `.npmrc`, `.pypirc`, `.netrc`, `.git-credentials`, `.htpasswd`, `.pgpass`, `.my.cnf`, `auth.json`, `auth.yaml`, `auth.yml`, `auth.toml`, `kubeconfig`, `api-token`, `api-unit-token`, `*.jks`, `*.keystore`, the key names `id_dsa`, `id_ecdsa_sk` and `id_ed25519_sk`, browser profile journals, the bridge's own `.edge-project-bridge` and `.edge-bridge-journal` folders, and leftover `.edge-bridge-tmp-*` staging files of the legacy Python service. A reviewer could read `.git/config` before. File listing, reading, search, delegated writes, snapshots for delegated runs, and the Git status, diff and diff summary of a remote principal all apply the rule. The local owner is not affected: reads, patches, journal recovery and the owner's Git status and diff show these paths as before. Most of the names come from the list of the legacy Python service; the two services still differ in other rules.
- The check that refuses a Git configuration with an `include` or `includeIf` section now reads the section headers at the start of each line: a byte order mark before the header and a header that follows another on one line are both recognised, and the word in a comment, a value or another section's name is not taken for an include. It stays stricter than Git: for example a value continued onto a line that begins with `[include]`, and a section named `[include.sub]`, are refused.
- The worker refuses a delegated run with `PERSISTENT_ENVIRONMENT_HOLDS_CREDENTIALS` while the user or machine environment kept in the registry holds an entry that looks like a credential, by a word in its name or by a value the secret scan recognises. A sandboxed run can read those keys although its process environment is cleared, and its output goes back to the requester. The refusal gives the count only. The new `edge-bridge environment-check` lists the names for the owner, and `worker --allow-environment-credentials` runs anyway. An entry whose value cannot be read as text counts too, and a key that cannot be read, or that changes while it is read, stops the run with `PERSISTENT_ENVIRONMENT_UNREADABLE`. The check is a guess from names and values made once per request, not a boundary.
- A reviewer's own files are kept out of queued runs. `powershell_script` refused nothing about where its script lived, so a script created under `_pro/` with `file_write` ran. A script inside any folder that a grant for the project has made writable is now refused with `SCRIPT_INSIDE_REQUESTER_WRITABLE_PATH`, in any letter case, and so is any script path with a component that holds `~` and a digit. `python_tests` no longer enters or counts those folders, so files placed there cannot reach the tested copy or use up its file budget. A grant with the write or patch category can queue a run only when `_pro/**` is its one writable path; `task_submit` and the worker both refuse any other. The worker refuses a delegated run when the state directory holds more than one registered project, and a run is refused at launch when a grant or project was added after its files were chosen. The rule works by folder and by the grants recorded in the state directory: a reviewer's file that the owner moves elsewhere, or a state directory that no longer holds the grant, is outside it.
- Output captured from a queued run no longer names the host directory the run executed in. The workspace is shown as `<workspace>` and the run directory as `<run>`.
- Delegated executor writes are create-only for executor and paired-host MCP connections. Each call is limited to 1 MiB per file and 4 MiB of content. Each granted folder is limited to 2,000 files and 256 MiB. The 8,192-entry scan cap includes proposed files and subdirectories. Remote file reads verify exact Windows paths through opened handles, reject short-name components, and hide internal stage entries. Delegated writes recheck the grant before each rename and verify the committed file through its staged handle, including on long paths. Rollback cleans up staged files and newly created empty directories and retains a recovery journal when cleanup leaves residue. Remote evidence uses an allowlist, and executor and paired-host evidence and run listings apply caller and grant filters before limiting results. The `grant-create --profile pro-review` profile grants read and Git read access, creation under `_pro/**`, and the `python_tests` and `powershell_script` recipes for 60 minutes by default.
- On the read-only `edge` connection the stdio MCP server runs tool calls concurrently on bounded workers and answers each as it completes. Connections that can change state keep answering one frame at a time, in order.
- The read-only connection admits 64 read and heavy calls plus 32 control calls at once. A call over the limit gets `RESOURCE_BUSY` with `retry_after_ms`. A call cancelled before it starts is dropped. A request id that is still in flight is refused.
- On Windows the stdio server and the Git processes it starts share a kill-on-close job, so no child outlives the server.
- The read-only connection exits when a write to the peer fails, and on Windows within about two seconds of the peer closing its end while the server is idle. Other connections end when their input closes or a write fails, as before.
- Read budgets: a Git read is refused above 64 MiB of output and a listing or manifest walk above 200000 entries, both with `RESOURCE_BUDGET_EXCEEDED`. File pages are cut by character boundaries and manifest files are hashed as a stream, so memory no longer grows with file size beyond the file itself.
- Git reads no longer run commands taken from the repository. `git_status`, `git_diff` and `git_diff_summary` are refused when the repository configuration sets a content filter (`filter.<name>.clean`, `smudge` or `process`) or includes another configuration file, and they no longer descend into nested repositories or submodules. `git_diff` and `git_diff_summary` leave out every path the file service refuses to read, at any depth, and accept only a commit as `base_ref`. `git_status` leaves the same paths out of its entries. A repository configuration with an `[include]` section is refused from the file itself, before any Git process runs. `git_status` reads renamed and unmerged records correctly.
- Directory walks count every entry they read against the 200000-entry budget before it is kept or sorted, so a directory larger than the budget is refused instead of held in memory. `file_search` is under the same budget. The `walkdir` dependency is removed.
- The legacy Python stdio MCP server accepts input that starts with a UTF-8 byte order mark and ignores blank lines. Windows PowerShell 5.1 under a UTF-8 console sent the mark before the first request, which made `scripts/recover-bridge.ps1` and the release tests fail depending on the console code page.
- `initialize` returns usage `instructions`, and every tool has its own description. Tools the connection cannot call say so.
- `mcp --text-content summary` sends a one-line text block and keeps the result in `structuredContent` only. The default stays `full`.

## V0.5.0 source prerelease

- Added bounded HTTP admission for control, common reads and heavy operations, with separate active and pending budgets per authenticated credential.
- Exposed request queue timing and structured retry guidance. Split HMAC replay windows by credential.
- Scoped the dashboard overview to the owner and filtered delegated run status, output and cancellation by the active grant.
- Kept queued runs across restart and guarded state transitions against concurrent cancellation. SQLite uses full synchronization for acknowledgements.
- Serialized patch and recovery for the same project root within the state directory, with hash-checked conflicts and preserved backups.
- Added an explicit environment label and immutable fixture-driven concurrency and failure rehearsal scripts.
- Packaged portable source and build instructions for a private canary.
