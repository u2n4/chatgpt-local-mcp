# Edge Project Bridge V0.4.0 — Security Boundaries & Negative Verification

This document lists concrete implementation-level enforcement points and the automated negative tests that verify each boundary.

| Security Boundary | Implementation Enforcement Location | Negative Verification Proof |
| --- | --- | --- |
| **`edge` Principal Strictly Read-Only** | `crates/bridge-core/src/policy.rs` (`PolicyEngine::authorize`), `crates/bridge-adapters/src/mcp.rs` (`McpDispatcher::dispatch_tool`) | Rust unit test `edge_stays_strictly_readonly_and_executor_respects_revocation_and_expiry` + live stdio MCP test (`file_write` -> `BRIDGE_POLICY_DENIED`) |
| **No Caller Principal Spoofing** | `crates/bridge-adapters/src/mcp.rs` (`tools/call` rejects any `principal` argument key) | Rust unit test + `scripts/run_v040_vertical_slice.py` (`INVALID_ARGUMENT`) |
| **Scoped Grant Revocation & Stale Policy Rejection** | `crates/bridge-core/src/policy.rs` checks `revoked`, `expires_at`, `host_id`, `policy_revision`, `writable_paths`, `allowed_recipes` fresh from SQLite | Rust unit test verifies writes outside `writable_paths`, unapproved recipes (`firmware_flash`), and post-revocation calls all fail closed |
| **Windows Path Hazards & Reparse / TOCTOU Protection** | `crates/bridge-platform/src/lib.rs` (`validate_relative_path`), `crates/bridge-platform/src/windows.rs` (`file_identity_no_follow`, `file_identity_from_handle`), `crates/bridge-core/src/files.rs` | Blocks `../`, `/abs`, `a\b`, `//unc/share`, `foo:ads`, `C:rel`, `CON`/`NUL`/`COM1`/`LPT9`, trailing `.`/` `, reparse points/junctions, and open-handle identity drift (`tests/security/test_v040_security.py`) |
| **Synthetic Secret Canary Denial** | `crates/bridge-core/src/files.rs` (`is_denied_secret_path`) + `crates/bridge-core/src/git.rs` (`:(exclude,icase,glob)`) | Denies `.env`, `secrets.js`, `*.pem`, `*.key`, `*.kdbx`, `Cookies`, `Login Data`, `owner.token`, `tunnel-runtime.key` using synthetic canaries only — never reads real user secrets |
| **Content-Level Secret Scanning Before Export** | `crates/bridge-core/src/evidence.rs` (`scan_and_redact_secrets`) | Scans raw payload bytes for PEM private keys, `sk-*`, `ghp_*`, `AKIA*`, `Bearer *`, JWTs, `password=/api_key=`, and emails; never trusts a static `redacted: true` flag |
| **Patch Preimage, Crash Recovery & User Edit Protection** | `crates/bridge-core/src/files.rs` (`apply_patch_plan`, `rollback_patch_journal`) | Rejects stale preimage with zero writes (`VERSION_CONFLICT`), recovers mid-apply crash via journal, and **refuses rollback** if current disk hash differs from `postimage_sha256` (protects later user edits) |
| **Idempotency & No Duplicate Mutation Replay** | `crates/bridge-core/src/state.rs` (`claim_durable_run`), `crates/bridge-core/src/jobs.rs` | Duplicate `operation_id` with identical payload returns existing `run_id`; duplicate `operation_id` with modified payload fails with `IDEMPOTENCY_PAYLOAD_MISMATCH` (`tests/security/test_v040_security.py`) |
| **Process-Tree Supervision & Containment Honesty** | `crates/bridge-platform/src/windows.rs` (`WinJobObject`, `probe_mxc_backend`) | Verified Win32 `TerminateJobObject` kills spawned child tree (`win32_job_object_terminates_spawned_child_tree`); `require_mxc=true` fails closed (`ISOLATION_NOT_VERIFIED`) outside `WinSta0\Default` rather than silently weakening |
| **Provider `INCLUDED_ONLY` & Alias Bypass** | `crates/bridge-adapters/src/providers.rs` (`resolve_provider_binary`, `validate_claude_launch_safety`, `parse_provider_ndjson`) | Direct `claude.exe` path bypasses shell `--dangerously-skip-permissions` alias; Claude `--bare` blocked under `INCLUDED_ONLY`; AGY soft-denied tools with exit 0 map to `BLOCKED`, never `PASS` |
| **Loopback UI Auth, Host, Origin & CSP** | `crates/bridge-cli/src/server.rs` (`validate_headers_and_auth`) | Verified unauthenticated `401`, cross-origin `Origin: https://evil.example` `403`, authenticated `200`, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, strict CSP |
| **Multi-Device Mutual Auth & Replay Guard** | `crates/bridge-adapters/src/devices.rs` (`DeviceChannel`) | One-time pairing token bound to cryptographic `host_id`, single-use consumption, 30s freshness window, Ed25519 verification, and nonce replay rejection |
| **Physical Hardware Actuation Hard-Denial** | `crates/bridge-adapters/src/hardware.rs` (`validate_telemetry_outgoing_message`) | Arm/disarm, takeoff, land, motor test, `PARAM_SET`, firmware flash, and unknown commands fail with `HARDWARE_ACTION_DENIED` |
